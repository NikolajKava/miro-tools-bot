# Видео → Miro: каталог инструментов

Вход: файл видео (или URL). Выход: строка в сводной таблице + карточка-документ на каждый инструмент.

**Доска:** берётся из переменной окружения `MIRO_BOARD_URL`.
**Язык всех описаний:** русский.

## Железные правила

1. **Ссылки не выдумывать.** URL попадает на доску, только если он реально открылся через WebFetch/WebSearch. Не подтвердилось — `⚠️ источник не подтверждён` и список кандидатов вместо ссылки.
2. **Команда установки — из README**, а не по памяти.
3. **Дедупликация обязательна** — доска накапливается из многих видео.
4. **Ничего не спрашивать.** Запуск неинтерактивный: все сомнения уходят в отчёт и в пометки на карточках.
5. **Не ставить тяжёлые зависимости** (torch, whisper) — уложиться в кадры и подпись.

## Шаг 1. Извлечь содержимое видео

### 1a. Метаданные и подпись

Если пришёл файл — подпись сообщения уже в промпте. Если пришёл только URL:

```bash
yt-dlp -o "work/video.%(ext)s" --write-info-json --write-auto-subs --sub-format vtt "$URL"
```

`description` из `info.json` часто содержит весь список названий. С IP GitHub Actions Instagram и TikTok обычно отдают ошибку — это ожидаемо, тогда честно сообщить, что нужен файл.

### 1b. Кадры — основной источник названий

Названия почти всегда на экране. Собирать контактные листы, а не сотни кадров:

```bash
ffmpeg -i work/video.mp4 -vf "fps=1/2,scale=480:-1,tile=4x4" -qscale:v 3 work/sheet_%02d.jpg
```

16 кадров на лист = 32 секунды видео. Читать листы инструментом Read, выписывать названия, команды, URL.
Мелкий текст — пересобрать участок крупнее: `-ss <start> -t <dur> -vf "fps=1,scale=720:-1,tile=3x4"`.

## Шаг 2. Проверить каждый инструмент

По каждому названию — WebSearch, затем WebFetch найденной страницы. Приоритет: GitHub → официальная документация → npm/PyPI.

Собрать: назначение своими словами (2–4 предложения), команду установки, ссылку на репозиторий, ссылку на доки, категорию.

Категории: `Маркетинг` · `Тексты` · `Дизайн` · `Видео` · `Контекст и токены` · `CLI` · `MCP`.

## Шаг 3. Записать на доску

Сначала прочитать текущее состояние — `board_list_items` и `table_list_rows` — и отбросить то, что уже есть.

**Сводная таблица** — создаётся один раз через `table_create`, дальше пополняется через `table_sync_rows`:

| Колонка | Тип |
|---|---|
| Инструмент | text (isTitle) |
| Категория | select |
| Что делает | text |
| Установка | text |
| Ссылка | link |
| Откуда | link (URL видео) |

**Карточка на инструмент** — `doc_create`, сетка 3 в ряд, шаг **x = 900, y = 1300**, ниже таблицы.

Про шаг по вертикали: карточка такого объёма занимает ~784×1105 px, поэтому шаг 900 даёт наложение рядов. Проверять раскладку через `canvas_read_as_svg` (он отдаёт реальные width/height), двигать — через `canvas_update_from_svg`: диff идёт по `data-miro-id`, частичный SVG безопасен, удаление только по явному `data-deleted="true"`.

Шаблон карточки:

```markdown
# <Название>
**Категория:** <...>   **Статус:** активно / бета / ⚠️ источник не подтверждён

## Зачем нужен
<2–4 предложения: какую проблему решает>

## Установка
`<команда из README>`

## Ссылки
- Репозиторий/сайт: <url>
- Документация: <url>
- Источник: <url видео>
```

## Шаг 4. Проверить и отчитаться

`board_list_items` + `table_list_rows`: число строк = число карточек, дублей нет, карточки не накладываются.

Отчёт в конце — простым текстом без markdown-заголовков (уйдёт в Telegram): что добавлено, что пропущено как дубль, что осталось с пометкой ⚠️.
