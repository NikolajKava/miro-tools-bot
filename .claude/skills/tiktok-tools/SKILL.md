# Видео → Miro: каталог инструментов

Вход: файл видео (или URL). Выход: строка в сводной таблице + карточка-документ на каждый инструмент.

**Доска:** берётся из переменной окружения `MIRO_BOARD_URL`, токен — из `MIRO_TOKEN`.
**Язык всех описаний:** русский.

## Железные правила

1. **Ссылки не выдумывать.** URL попадает на доску, только если он реально открылся через WebFetch/WebSearch. Не подтвердилось — `⚠️ источник не подтверждён` и список кандидатов вместо ссылки.
2. **Команда установки — из README**, а не по памяти.
3. **Дедупликация обязательна** — доска накапливается из многих видео.
4. **Ничего не спрашивать.** Запуск неинтерактивный: все сомнения уходят в отчёт и в пометки на карточках.
5. **Не ставить тяжёлые зависимости** (torch, whisper) — уложиться в кадры и подпись.

## Шаг 1. Извлечь содержимое видео

### 1a. Метаданные и подпись

Если пришёл файл — подпись сообщения уже в промпте. Если пришёл только URL:

```bash
yt-dlp -o "work/video.%(ext)s" --write-info-json --write-auto-subs --sub-format vtt "$URL"
```

`description` из `info.json` часто содержит весь список названий. С IP GitHub Actions Instagram и TikTok обычно отдают ошибку — это ожидаемо, тогда честно сообщить, что нужен файл.

### 1b. Кадры — основной источник названий

Названия почти всегда на экране. Собирать контактные листы, а не сотни кадров:

```bash
ffmpeg -i work/video.mp4 -vf "fps=1/2,scale=480:-1,tile=4x4" -qscale:v 3 work/sheet_%02d.jpg
```

16 кадров на лист = 32 секунды видео. Читать листы инструментом Read, выписывать названия, команды, URL.

Кадр в таком ролике устроен так: скринкаст сверху, говорящий снизу — поэтому в контактном листе полосы идут парами и легко ошибиться в подсчёте рядов. Тайл N на листе K соответствует `t = (K-1)*32 + (N-1)*2` секунд.

**Для каждого инструмента запомнить секунду, на которой он опознан** — тот кадр, где видно название: страница репозитория, README, строка поиска. Этот кадр пойдёт на доску.

Мелкий текст — пересобрать участок крупнее и с точной привязкой ко времени:

```bash
ffmpeg -i work/video.mp4 -vf "select='between(t,44,59)',fps=1,scale=360:-1,tile=4x4" -qscale:v 3 -frames:v 1 work/zoom.jpg
```

Тут тайл N соответствует `t = 44 + (N-1)`. Именно `select`, а не `-ss` перед `-i`: быстрый seek промахивается на несколько секунд, и подпись под кадром перестаёт совпадать с картинкой.

### 1c. Вырезать кадр под каждую карточку

```bash
ffmpeg -i work/video.mp4 -vf "select='gte(t,<секунда>)',scale=540:-1" -frames:v 1 -qscale:v 2 work/shot_<slug>.jpg
```

## Шаг 2. Проверить каждый инструмент

По каждому названию — WebSearch, затем WebFetch найденной страницы. Приоритет: GitHub → официальная документация → npm/PyPI.

Собрать: назначение своими словами (2–4 предложения), команду установки, ссылку на репозиторий, ссылку на доки, категорию.

Категории: `Маркетинг` · `Тексты` · `Дизайн` · `Видео` · `Контекст и токены` · `CLI` · `MCP`.

## Шаг 3. Записать на доску

Запись идёт через `scripts/miro_card.py` — REST API с токеном из `MIRO_TOKEN`.

**MCP-сервер Miro здесь не работает**: `mcp.miro.com` отвечает `403` на токены приложений, он принимает только собственный браузерный OAuth. Приватный docs API закрыт белым списком (`app is not whitelisted`), таблицы через REST тоже не создаются. Поэтому каталог живёт на карточках — их REST создаёт, двигает и удаляет без ограничений.

Сначала посмотреть, что уже есть, и отбросить дубли:

```bash
python scripts/miro_card.py list
```

Затем по карточке на инструмент:

```bash
python scripts/miro_card.py add \
  --title "Stop Slop" \
  --category "Тексты" \
  --purpose "2–4 предложения: какую проблему решает" \
  --install "команда из README" \
  --link "https://github.com/..." \
  --docs "https://..." \
  --source "<url видео>" \
  --screenshot work/shot_stopslop.jpg
```

Скрипт сам ставит цвет по категории, кладёт карточку в следующую свободную ячейку сетки (4 в ряд) и молча пропускает дубль по названию. Скриншот ложится над карточкой в той же ячейке — по нему сразу видно, где инструмент попался в ролике. `--screenshot` указывать всегда, если кадр удалось вырезать. Категории — из списка выше; незнакомая получит серый цвет.

Если источник не подтвердился, всё равно добавить карточку: в `--title` добавить `⚠️ источник не подтверждён`, в `--purpose` перечислить кандидатов, `--link` не заполнять.

## Шаг 4. Проверить и отчитаться

`python scripts/miro_card.py list` — убедиться, что все инструменты на месте и дублей нет.

Отчёт в конце — простым текстом без markdown-заголовков (уйдёт в Telegram): что добавлено, что пропущено как дубль, что осталось с пометкой ⚠️.
